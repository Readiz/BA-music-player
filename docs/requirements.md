# Readiz Music 핵심 요구사항

2026-10-23 기준의 기능 계약과 확인 경로다. 첫 정리는 커밋 `3eee74dc3fceb8581045d5a62dde34be74ae83c8`의 소스와 운영 문서를 기준으로 했다. 당시 작업 트리는 깨끗했다. 문서 작성 중 기능 테스트, 운영 로그인, 음원 추가, 배포는 실행하지 않았다.

`구현 있음`은 해당 소스와 검증 코드가 있다는 뜻이다. 운영 반영이나 실기기 검증 완료를 뜻하지 않는다. 과거 검증 결과는 [운영 안내](../ops/README.md), [Android 안내](../android/README.md), [Tizen 안내](../tizen/README.md)에 보존하며, 이 문서는 반복해서 확인할 현재 동작을 모은다.

## 기능 계약과 수용 조건

### MUSIC-01 로그인별 앨범 접근

로그인 전에는 정확한 앨범 경로 `Blue Archive`, `th original`만 표시하고 재생한다. 나머지 앨범과 음악 추가는 기존 Readiz SSO의 허용 계정 정책을 따른다. 목록만 감추는 것으로 끝내지 않고 메타데이터, 파형, 표지와 음원 직접 요청에도 권한을 적용한다.

- 수용 조건: 비로그인 카탈로그와 직접 음원 요청에서 다른 앨범이 노출되지 않는다. 로그인 후 허용 목록이 갱신되고, 로그아웃이나 세션 만료가 확인되면 기존 재생을 멈추고 공개 목록으로 돌아간다.
- 수용 조건: 계정용 앨범/곡 선택 키와 `-public` 키를 분리한다. 비로그인 초기값이 저장된 계정 선택을 덮어쓰지 않는다. 카탈로그와 음원 응답은 `private, no-store`와 `Vary: Cookie, Origin`을 사용한다.
- 수용 조건: 서비스 워커는 `/_auth`, `/api/auth`와 하위 경로, 정확한 `/login`·`/login/` 문서 이동을 가로채지 않는다. iframe 여부를 포함한 브라우저 탐색 메타데이터를 SSO까지 유지하고, OAuth callback에 오프라인 화면을 대신 반환하지 않는다. 일반 페이지의 오프라인 안내와 음원·카탈로그의 네트워크 처리는 유지한다. 새 워커는 오프라인 문서 준비가 성공한 뒤 대기를 건너뛰고, 기존 캐시 정리 뒤 열린 클라이언트를 제어한다. 페이지·재생을 새로고침하지 않으며 설치가 실패하면 기존 워커를 유지한다.
- 구현: [서버 접근 규칙](../server/catalog-access.mjs), [API 연결](../server/app.mjs), [웹 접근 갱신](../js/catalog-access.js).
- 검증 위치: [카탈로그 접근 검사](../scripts/catalog-access.test.mjs), [인증 검사](../scripts/auth.test.mjs), [서비스 워커 검사](../scripts/service-worker.test.mjs), [격리 fixture](../scripts/access-fixture.mjs). 실제 계정 인증 결과는 별도 기록한다.
- 2026-10-25 상태: 웹 1.5.15 (`065c2bc`) 정적 배포를 완료했다. 전체 94개 검사와 기존 워커의 교체·문서/입력 보존을 확인했고, SW가 제어하는 Music 내부 로그인 링크에서 연결 화면을 거쳐 같은 홈 탭의 중앙 로그인 화면까지 이동했다. 실제 Discord 계정 로그인과 물리 Android 완료는 별도다.

### MUSIC-02 앨범과 곡 선택

폴더를 앨범으로 구성하고 여러 앨범을 함께 선택한다. 처음 방문했을 때 저장값이 없으면 Blue Archive를 선택한다. 앨범 전체 선택, 전체 해제, 패널 접기와 선택 복원을 제공한다. 패널을 접어도 선택과 재생 위치는 유지한다.

- 수용 조건: 일반 웹과 Android 휴대전화의 앨범은 한 줄로 배치하고 좌우로 스크롤한다. 페이지 전체가 가로로 넘치지 않으며 터치·키보드로 마지막 앨범까지 접근한다. 스크롤만으로 선택·재생을 바꾸지 않는다. TV의 기존 세로 목록은 유지한다.

곡 선택은 편집과 적용을 구분한다. 편집 중에는 기존 큐를 유지하고, 취소하거나 앨범을 변경하면 편집 내용을 버린다. `선택 재생`을 누르면 선택한 곡만 큐에 포함한다.

- 수용 조건: 앨범 변경 후 현재 곡이 남아 있으면 위치와 재생 상태를 보존한다. 현재 곡이 빠지면 남은 큐에서 무작위 모드에 맞춰 새 곡을 준비한다. 앨범을 모두 해제하면 재생을 멈추고 재생 버튼을 비활성화한다.
- 수용 조건: 곡 선택 적용 시 현재 곡이 남아 있으면 그 위치에서 재생하고, 빠졌으면 새 큐의 첫 곡을 재생한다. 0곡 선택은 적용하지 않는다. 이전/다음, 무작위, 자동 다음 곡과 네이티브 큐가 같은 선택을 따른다.
- 수용 조건: 전체 선택한 앨범에는 이후 추가된 곡을 포함하고, 일부 곡만 선택한 앨범에는 임의로 포함하지 않는다. 사라진 곡과 손상된 저장값을 처리하고, 저장할 수 없는 환경에서도 현재 재생은 동작한다.
- 구현: [목록 구성](../js/library.js), [플레이어](../js/script.js), [곡 선택 모델](../js/track-selection.js).
- 검증 위치: [곡 선택 단위 검사](../scripts/track-selection.test.mjs), [앨범 브라우저 검사](../scripts/verify-albums.js), [곡 선택 브라우저 검사](../scripts/verify-track-selection.js).

### MUSIC-03 재생과 파형

독립 웹에서는 오디오 요소 하나가 재생을 맡는다. 최초 방문, 목록 재시도, 저장값 복원만으로 자동 재생하지 않는다. 사용자의 재생 버튼, 곡 선택 또는 유효한 Space 입력에서 재생을 요청한다. 파형 로딩 실패가 오디오 재생이나 다음 곡을 막지 않아야 한다.

- 수용 조건: 입력칸, 체크박스, 버튼, 링크, 조합 입력과 반복 키의 기본 동작을 Space 단축키가 가로채지 않는다. 브라우저가 재생을 거부하면 일시정지 상태와 재시도 경로를 남긴다.
- 수용 조건: 한 곡 반복, 자동 다음 곡, 무작위와 위치 탐색이 현재 큐 안에서 동작한다. 탭 전환만으로 재생을 멈추거나, 돌아왔다고 사용자가 멈춘 곡을 다시 켜지 않는다.
- 수용 조건: 지원되는 Media Session에 곡명, 표지, 재생 상태, 위치와 이동 명령을 연결한다. 미지원 API와 파형 오류는 기본 재생을 유지한다. 확인되지 않은 곡명을 추측해서 붙이지 않는다.
- 구현: [플레이어](../js/script.js), [목록과 곡명](../js/library.js), [음원 주소](../js/music-source.js).
- 검증 위치: [시작 검사](../scripts/verify-startup.js), [백그라운드 검사](../scripts/verify-background.js), [파형 검사](../scripts/verify-waveform.js). 제어된 Chromium 검사는 물리 기기의 절전과 화면 잠금을 대신하지 않는다.

### MUSIC-04 홈페이지 위젯 동기화

홈페이지에서 여는 지정된 Music iframe은 부모의 오디오 하나를 함께 제어한다. 먼저 사용한 쪽의 곡, 위치와 큐를 이어받고, 창을 닫거나 최소화해도 재생은 이어진다. 독립 탭과 Android, TV에는 이 경로를 적용하지 않는다.

- 수용 조건: 위젯과 음악 창의 재생/일시정지, 탐색, 이전/다음, 선택 큐와 반복/자동 다음/무작위 상태가 일치한다. 늦은 초기 응답이 이후 사용자 조작을 덮어쓰지 않는다.
- 수용 조건: 정확한 부모/자식 창, 허용 origin, 연결 nonce와 명령 순서를 확인한다. 연결 실패 때 별도 오디오를 생성하지 않고 다시 불러오기를 안내한다.
- 구현: [Music 연결](../js/desktop-player.js), [네이티브 공통 어댑터](../js/native-player.js). 부모 구현과 큐/위치 저장은 홈페이지 저장소에서 관리한다.
- 검증 위치: [Music 연결 단위 검사](../scripts/desktop-player.test.mjs). 홈페이지 브라우저 검사는 [운영 안내](../ops/README.md)의 `verify-music-sync.js`, `verify-music-access.js` 절차를 따른다. 양쪽 릴리스의 조합을 함께 확인한다.

### MUSIC-05 YouTube와 파일 추가

허용 계정이 YouTube 영상 하나 또는 로컬 음악 파일 하나를 ETC에 추가한다. TV에서는 감상만 제공한다. 파일 업로드는 지원 확장자와 실제 오디오 형식 모두를 확인하며 원본 해시로 중복을 판정한다. YouTube는 정규화된 영상 ID로 중복을 판정한다.

- 수용 조건: 한 곡 최대 30분, 입력 최대 100MiB, 대기열 5개, 계정당 시간당 20곡, 누적 10GiB와 남은 공간 500MiB 제한을 적용한다. 파일 업로드는 계정당 동시 전송 1개와 전송 시간 10분을 제한한다.
- 수용 조건: 다운로드/전송, 변환, 동기화, 완료/실패를 구분한다. 서버가 수신한 작업은 창을 닫아도 이어지고, 재방문 시 해당 계정의 최근 상태를 복원한다. 전송 중인 파일은 완료 전 페이지 이탈과 구분한다.
- 수용 조건: NAS 백업과 게시 객체, 목록과 파형 검증을 마친 뒤에만 완료로 표시한다. 비공개 ETC는 익명 HTTP 성공을 요구하지 않고 검증된 NAS 서빙 객체와 현재 목록을 대조한다. 실패한 동기화는 준비된 MP3를 보존해 재사용한다.
- 구현: [추가 API와 제한](../server/imports.mjs), [동기화](../server/local-sync.mjs), [추가 화면](../js/import.js), [진단 정보 제한](../server/import-log.mjs).
- 검증 위치: [YouTube 검사](../scripts/imports.test.mjs), [업로드 검사](../scripts/uploads.test.mjs), [진행 표시 검사](../scripts/verify-import-progress.js), [업로드 브라우저 검사](../scripts/verify-upload.js), [로그인 복귀 검사](../scripts/verify-login-return.js). 이 검사는 운영 라이브러리에 시험 음원을 추가할 이유가 아니다.

### MUSIC-06 NAS 검증과 게시

Mac이 앱과 카탈로그를 제공하고 Caddy가 `readiz_static/music`의 읽기 전용 NAS 마운트에서 음원을 읽는다. 비공개 `readiz_private`의 백업 디렉터리는 서빙하지 않는다. Mac 복구 사본은 유지하며 같은 NAS의 게시본과 백업을 독립 백업으로 세지 않는다.

- 수용 조건: 실제 SMB 원본, 계정, 읽기/쓰기 상태와 여유 공간을 확인한다. 경로 존재만으로 NAS라고 판단하지 않으며 연결 상실 때 로컬 대체 폴더에 쓰지 않는다.
- 수용 조건: 크기와 SHA-256을 확인한 음원 객체만 재사용한다. NAS 쓰기와 읽기 경로의 검증이 끝난 후 현재 목록을 원자적으로 전환한다. 실패하면 이전 목록과 준비 파일을 보존한다.
- 수용 조건: 현재 카탈로그 밖 경로, 심볼릭 링크, 위조 객체와 내부 API의 외부 요청을 거부한다. 허용 음원은 GET/HEAD와 탐색용 Range를 지원한다. NAS가 없으면 음원은 실패하고 작은 앱 화면과 목록은 Mac에서 유지한다.
- 구현: [라이브러리](../server/library.mjs), [NAS 게시와 경로 검사](../server/nas-static.mjs), [게시 명령](../scripts/library.mjs), [연결 복구](../scripts/mount-static.mjs).
- 검증 위치: [라이브러리 검사](../scripts/library.test.mjs), [NAS 검사](../scripts/nas-static.test.mjs), [게시 검사](../scripts/library-publication.test.mjs), [마운트 복구 검사](../scripts/mount-static.test.mjs). 실제 연결과 읽기/해시 검증은 운영 작업 때 별도로 수행한다.

### MUSIC-07 Android 재생과 위젯

Android의 Media3 서비스가 재생과 큐를 소유하고 웹은 그 상태를 표시한다. 알림, 잠금화면과 홈 화면 위젯은 같은 서비스를 제어한다. 현재 소스 설정은 `com.readiz.music`, 앱 `0.4.4`이다.

- 수용 조건: 앱 복귀나 웹 화면 재생성 뒤에도 서비스의 곡, 위치와 큐를 복원하고 웹 오디오를 중복 재생하지 않는다. 서비스 종료 후 저장값을 복원해도 사용자 입력 전에는 자동 재생하지 않는다.
- 수용 조건: 위젯 크기에 따라 표지와 재생 버튼을 우선 표시하고, 여러 위젯이 같은 상태를 유지한다. Music 세션 쿠키는 같은 HTTPS 호스트의 음원과 허용 표지에만 전달한다.
- 수용 조건: 로그인은 외부 브라우저의 일회용 ticket/verifier 교환으로 복귀한다. 업데이트는 APK 크기, 해시, 패키지와 버전을 확인하고 Android 설치 확인을 거친다. 기존 정식 서명키를 유지한다.
- 수용 조건: 일반 로그인은 플레이어로 복귀하며 음악 추가 창을 열지 않는다. 추가 창에서 시작한 로그인만 명시적인 `/#add-music` 목적지를 보존한다. 쿠키 저장 완료 후 새 문서로 카탈로그를 요청하여 한 번의 로그인으로 계정 앨범·상단 로그인 상태를 갱신한다. 앱이 종료되었다가 복귀해도 쿠키 교환 전에 비로그인 목록을 요청하지 않고, 만료·실패 시 기본 화면과 재시도 안내를 표시한다.
- 구현: [재생 서비스](../android/app/src/main/java/com/readiz/music/PlaybackService.java), [저장 상태](../android/app/src/main/java/com/readiz/music/PlaybackSnapshot.java), [위젯](../android/app/src/main/java/com/readiz/music/MusicWidget.java), [쿠키 범위](../android/app/src/main/java/com/readiz/music/MusicCookies.java), [Android 빌드](../android/app/build.gradle).
- 검증 위치: [Android 단위 검사](../android/app/src/test/java/com/readiz/music/), [웹/네이티브 시간 검사](../scripts/native-player.test.mjs), [APK 게시 검사](../scripts/android-release.test.mjs), [기기 검증 범위](../android/README.md).

### MUSIC-08 TV 리모컨과 실행기

TV 화면은 방향키, 확인, 뒤로와 미디어 키로 앨범, 곡 선택, 재생과 탐색을 조작한다. 현재 Tizen 설정은 실행기 `0.1.1`, Tizen 5.0 이상이며 미서명 WGT를 만든다. 과거 안내의 `0.1.0` 파일명은 당시 기록으로 구분한다.

- 수용 조건: 선택/자동 곡 전환 때 포커스와 스크롤 위치를 맞추되 앨범, 도구와 편집 중 포커스를 빼앗지 않는다. 탐색은 5초 단위로 움직이며 일시정지 상태를 유지한다.
- 수용 조건: 뒤로는 곡 선택 취소나 탐색 종료를 먼저 처리하고 종료 확인으로 이어진다. 취소하면 직전 포커스로 돌아간다. 웹에 Tizen API가 없으면 로컬 실행기로 돌아가 종료한다.
- 수용 조건: Android TV의 출력 모드와 1920px 뷰포트 처리는 해당 앱에만 적용한다. 실제 출력 전환은 기기 지원 여부에 따르며, TV 홈 이동이나 전원 종료 뒤의 백그라운드 재생을 보장하지 않는다.
- 구현: [리모컨](../js/remote.js), [TV 화면](../js/tv-mode.js), [실행기](../tizen/launcher.js), [현재 Tizen 설정](../tizen/config.xml).
- 검증 위치: [TV 브라우저 검사](../scripts/verify-tv.js), [실행기 검사](../scripts/verify-tizen.js), [뷰포트 검사](../scripts/tv-viewport.test.mjs), [실기기 확인 항목](../tizen/README.md).

### MUSIC-09 코드 배포와 복구

코드 배포와 음원 게시를 분리한다. 소스만 받은 저장소에서도 테스트와 웹 빌드를 수행할 수 있어야 한다. 코드 릴리스 때문에 기존 음원과 공개 목록을 다시 게시하지 않는다.

- 수용 조건: 공개 빌드에는 런타임과 설치 자산만 들어가며 인증 설정, 요청 이력, 세션 DB, 서명키와 비공개 원본은 포함하지 않는다. 운영 APK와 메타데이터가 불일치하면 배포를 거부한다.
- 수용 조건: 깨끗한 의도된 커밋에서 선택한 Music 릴리스만 배포한다. 홈페이지 동기화 변경은 양쪽 배포 순서와 원복 조합을 따른다. 음원이 없는 새 서버는 NAS 검증본에서 복원한다.
- 구현과 검증: [빌드](../scripts/build.mjs), [빌드 경계 검사](../scripts/build.test.mjs), [운영 배포](../scripts/deploy-local.mjs), [운영과 복구 절차](../ops/README.md).

## 다음 검증에서 남길 기록

자동 검사는 `npm test`의 해당 단위/통합 검사와 기능별 브라우저 스크립트를 구분해서 기록한다. Android 빌드 검사는 [Android 안내](../android/README.md)를 따른다. 문서 변경만 한 이번 정리는 테스트 통과 횟수를 새로 만들지 않았다.

## 2026-10-23 소스와 운영 대조

후속 점검의 시작 커밋은 `d51ee29`이며 작업 트리는 깨끗했다. 운영 웹은 `41d2286e6bc3`의 1.5.14 릴리스, API는 `577437b9a98e` 릴리스를 사용한다. 두 커밋이 다르다는 사실만으로 코드 누락으로 판단하지 않고 각 배포 경계를 대조했다.

- 현재 `dist/`와 운영 웹 릴리스의 파일 51개는 SHA-256이 모두 같으며 양쪽에만 있는 파일은 없었다. 웹 릴리스 이후 HEAD까지의 변경은 README, 운영 안내와 요구사항 문서뿐이었다.
- API의 `server/` 파일 15개와 `scripts/mount-static.mjs`는 현재 소스와 모두 같으며 운영 서버에만 있는 소스 파일도 없었다. API 건강 응답의 revision도 해당 실행 릴리스와 일치했다.
- 공개 HTTPS의 `index.html`, `app-config.json`, `css/style.css` 응답 바이트가 운영 파일과 일치했다. 이는 제공 파일의 확인이며 로그인, 실제 음원 재생과 물리 기기 검증을 새로 수행했다는 뜻은 아니다.
- 배포할 제품 코드 차이가 없어 웹/API 재배포, 서비스 재시작, 음원 재게시와 NAS 파일 변경을 하지 않았다. 요구사항 문서를 원격에 반영하는 작업과 런타임 교체를 구분한다.
